# AI LINE CRM 要件定義ドラフト

## 1. プロジェクト名

AI LINE CRM MVP for LINE Harness

## 2. 目的

LINE公式アカウントを、リード獲得、目的診断、AI相談窓口、ナーチャリング、商談化のハブとして構築する。

## 3. 背景

SNS、note、LP、YouTube、TikTok、勉強会などから流入する見込み客を、LINE上で分類し、目的に合った特典・事例・講座・相談導線へ接続する必要がある。最初から売り込まず、目的選択とタグ管理により自然に温度を上げる。

## 4. 対象ユーザー

- AI初心者
- AIを仕事で使いたい個人、フリーランス
- AIエージェント導入を検討する法人、経営者、チーム責任者
- 業務効率化、自動化を相談したい人
- AI講座、ブートキャンプ、勉強会に興味がある人
- 研修、顧問、制作、導入支援を依頼したい人

## 5. 解決したい課題

- 登録者全員に同じ配信をしてしまい、興味別の導線が弱くなる
- LINE登録後の目的分類ができず、商談候補を見逃す
- 無料特典、勉強会、個別相談、講座、導入支援への接続が分断される
- 手動対応すべき高温度リードの判定基準が曖昧になる

## 6. 現在の業務フロー

SNS、note、LP、セミナーから個別に問い合わせやフォローが発生し、相談希望者の状況整理、特典配布、勉強会案内、予約誘導が手動または散発的に行われる。

## 7. 理想の業務フロー

LINE登録 -> 初回目的選択 -> タグ付与 -> 無料特典案内 -> 7日間ナーチャリング -> 勉強会または個別相談 -> ヒアリング -> 提案 -> 成約。

## 8. 自動化対象

- 初回あいさつ
- 目的選択メニュー
- 興味、課題、温度感、商品タグの初期作成
- 7日間ステップ配信
- 目的別の補助シナリオ
- キーワード自動返信
- 相談ヒアリングフォーム
- 商談候補タグ付け

## 9. 人間が確認する範囲

- 高温度リードの個別返信
- 相談フォーム送信後の内容確認
- 具体的な提案、見積もり、契約判断
- AIエージェント導入や法人研修の要件ヒアリング

## 10. 対象範囲

MVPでは、LINE Harness の既存機能を使い、タグ、シナリオ、フォーム、自動返信、リッチメニュー定義を構築する。

## 11. 除外範囲

- 有料決済の実装
- 予約システム本体の開発
- 無料特典PDFそのものの制作
- リッチメニュー画像の最終デザイン制作
- OpenAI等を使った自由会話AIの本番連携

## 12. 入力情報

- LINE友だち追加イベント
- 初回メニューの数字/キーワード返信
- リッチメニュークリック
- 相談フォーム送信
- 予約ページ、料金ページ、事例ページのクリック

## 13. 処理内容

- 目的別タグと温度感タグを付与
- 友だち追加時に共通7日間シナリオへ登録
- 特定タグ追加時に補助シナリオを開始
- 相談フォーム送信時に商談候補タグを付与
- 行動ログをもとに月次で導線改善する

## 14. 出力情報

- LINEメッセージ
- 自動返信
- ステップ配信
- 相談フォーム回答
- タグ付き友だちリスト
- KPI確認用の管理画面データ

## 15. 使用ツール候補

- LINE Harness
- Cloudflare Workers
- Cloudflare D1
- Cloudflare Pages / Next.js 管理画面
- LINE Messaging API
- LIFF フォーム
- Google Calendar または外部予約ページ
- MCP Server / SDK

## 16. データ構造

| 項目名 | 内容 | 必須 | 例 |
|---|---|---|---|
| friendId | LINE Harness内の友だちID | はい | `uuid` |
| lineUserId | LINEユーザーID | はい | `Uxxxxxxxx` |
| displayName | 表示名 | いいえ | `山田太郎` |
| tags | 興味、課題、温度、商品タグ | はい | `興味_AIエージェント` |
| funnelStage | 商談ステージ | いいえ | `Stage 5` |
| selectedPurpose | 初回目的選択 | いいえ | `AIを仕事で使えるようになりたい` |
| currentIssue | 現在の課題 | いいえ | `社内導入が進まない` |
| customerType | 個人/法人 | いいえ | `法人` |
| preferredContact | 希望相談方法 | いいえ | `Zoom` |
| leadTemperature | 温度感 | はい | `温度_高` |
| lastAction | 最終行動 | いいえ | `相談フォーム送信` |

## 17. AIエージェントの役割

- Orchestrator Agent: 配信、タグ、フォーム、予約導線の整合を確認する
- Requirement Agent: 導線改善、シナリオ追加、フォーム項目の調整を設計する
- Drafting Agent: 配信文、FAQ、講座案内、相談誘導文を作成する
- QA Agent: 売り込み過多、導線矛盾、タグ漏れ、個人情報ログを確認する

## 18. ワークフロー設計

1. 友だち追加で共通7日間シナリオを開始
2. 初回メッセージで8択を提示
3. 数字/キーワード返信で自動返信
4. タグで興味、課題、温度感を管理
5. 特典、Tips、事例、勉強会、講座、個別相談へ段階誘導
6. 相談フォーム送信で商談候補化
7. 人間がヒアリング、提案、成約へ進める

## 19. UI / 画面要件

- リッチメニューは6項目: 無料ガイド、AI診断、導入相談、AI講座、勉強会、質問する
- 管理画面ではタグ、シナリオ、フォーム、友だち一覧、会話を確認できること
- フォームはMVPでは5項目に抑え、離脱を防ぐ

## 20. 通知要件

MVPではLINE Harness管理画面で商談候補タグを確認する。将来的にはSlack、メール、Webhookで高温度リードを通知する。

## 21. 権限・セキュリティ要件

- APIキー、LINEトークン、チャネルシークレットは環境変数またはWrangler secretで管理する
- 個人情報を不要にログへ残さない
- 管理画面はOwner/Admin/Staff権限を使う
- 相談フォームの外部Webhook連携時は送信先と保持期間を確認する

## 22. エラー処理

- API投入スクリプトは既存タグ、既存シナリオ、既存フォームを検出して重複作成を避ける
- 外部URL未確定の場合は `https://example.com/...` を仮置きし、本番前に差し替える
- LINE APIのリッチメニュー作成や画像アップロード失敗時は管理画面またはAPIで再実行する

## 23. ログ・履歴管理

- messages_log で配信履歴を保存
- form_submissions で相談内容を保存
- friend_tags で分類履歴を管理
- 月1回、KPIを確認して初回メッセージ、CTA、特典、配信タイミングを改善する

## 24. MVP範囲

- あいさつメッセージ
- 目的選択
- リッチメニュー6項目
- 無料特典3種類へのリンク
- 共通7日間ステップ配信
- AIエージェント導入フォロー
- 勉強会フォロー
- 相談ヒアリングフォーム
- FAQ/キーワード自動返信
- タグ設計

## 25. 将来的な拡張

- タグ付与アクション付きの高度な自動返信
- 行動スコアに応じた温度感自動更新
- Slack通知

- AI自由相談ボット
- 商品別LPと決済連携
- 参加後アンケートと講座提案自動化

## 26. 成功条件

- 友だち追加後に目的選択へ進む
- 目的別にタグ分類できる
- 7日間で特典、Tips、事例、勉強会、相談へ自然に誘導できる
- 商談候補が管理画面で抽出できる

## 27. 完了条件

# 自動化ワークフロー案

## Step 1. Trigger

友だち追加、数字/キーワード返信、リッチメニュークリック、フォーム送信。

## Step 2. Input Collection

初回目的、相談内容、現在の課題、個人/法人、希望相談方法を取得する。

## Step 3. Pre-processing

タグ、温度感、ステージへ変換する。URLや予約導線が未確定の場合は仮URLを使う。

## Step 4. AI Processing

MVPではAI自由会話は対象外。運用改善時に配信文、FAQ、提案前メモの生成に使う。

## Step 5. System Processing

LINE Harnessがシナリオ配信、自動返信、フォーム保存、タグ管理、ログ保存を行う。

## Step 6. Human Review

商談候補、相談フォーム送信者、料金閲覧者は人間が内容を確認し、必要に応じて返信する。

## Step 7. Final Output

ユーザーには目的別の特典、勉強会、講座、個別相談案内を配信する。運営側にはタグ付きリードとフォーム回答が残る。

## Step 8. Logging

配信履歴、フォーム送信、タグ、クリック、会話履歴を保存する。

## Step 9. Error Handling

LINE API、フォーム、外部予約リンク、Webhookの失敗を検知し、管理画面で再確認する。

## Step 10. Improvement Loop

週次で配信文とCTA、月次でKPI、四半期で商品導線と特典を見直す。
