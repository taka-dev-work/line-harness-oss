# 既存 D1 の差分チェック：分かっていること・限界

`pnpm db:drift:client` と `pnpm db:adopt:client` の前提と限界です。

## 確認していること

- `0000_baseline.sql` にあるテーブルと列が、その D1 に**名前として**存在するか
- 読み取りはテーブルの一覧と、テーブルごとの `PRAGMA table_info` だけ。リモートの D1 は `pragma_table_info()` を関数として使う書き方を拒否するため（`SQLITE_AUTH`）
- `_cf_` で始まるテーブル（Cloudflare の内部用）と `d1_migrations` は対象外

## 確認していないこと（既知の限界）

- **列の型・既定値・NOT NULL・CHECK が違っていても検出しない。** 名前が一致すれば「ある」とみなす。古い D1 で手作業の変更をしたことがあるなら、移行前にエクスポートしたスキーマ（`d1 export --no-data`）と `0000_baseline.sql` を目で見比べる
- 同名で定義の違うインデックスはそのまま残る（`CREATE INDEX IF NOT EXISTS` は何もしない）
- 初期スキーマにない余分なテーブルは情報として表示するだけで、消さない

## 移行ツールが止まる場合

`ALTER TABLE … ADD COLUMN` で作れない列が不足していると、SQL を出さずに `cannot ADD COLUMN <table>.<column>` で止まります。対象は次の通りで、その列だけ手作業の移行（新テーブルへのコピー）が必要です。2026-11-26 時点のクライアント0号では該当なし。

- 主キー、既定値なしの NOT NULL
- CHECK・UNIQUE・COLLATE・GENERATED 付き
- 定数でない既定値（`datetime('now')` などの式、`CURRENT_TIMESTAMP`）
- 外部キーで、既定値が NULL 以外
- 初期スキーマの中で列の定義を特定できないもの

定数でない既定値と外部キーの組み合わせは、SQLite が**テーブルに行があるときだけ**拒否します。スキーマだけのコピー（行がない）でのリハーサルでは検出できないため、ツール側で先に止めています。それ以外にも行がある状態でだけ起きる失敗はあり得るので、本番適用は必ずエクスポートと Time Travel のブックマークを取ってから行います（適用は一括で、失敗すれば元の状態に戻ります）。
